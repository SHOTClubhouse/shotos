# The six guardrails

The [twelve controls](../README.md) say how an agent and a person work on a task. The guardrails say what has to stay true across every task and every stage, however well the controls are followed. Each guardrail protects one thing, sets a minimum practice and lists the checks that show it is holding.

|---|---|---|---|

## How guardrails relate to controls and stages

- A **control** is something an agent and a person do on a task. A **guardrail** is a standing condition the controls help to maintain.
- Guardrails apply in all six stages. Scope sets which guardrails matter most for this work. Operate and Track test them. Own and Sustain and Scale keep them true after the team that built the work has gone.
- If a guardrail and a task conflict, the guardrail wins and the owner is told.

## Using the pages

Each page has the same four parts:

1. **What it protects**: the thing at risk and who loses if it fails.
2. **Minimum practice**: the smallest set of habits that counts as having the guardrail.
3. **Checks**: observable tests you can run, in under an hour, to see whether it is holding.
4. **Controls and skills**: which controls carry the load, and which skills help.

Start with the minimum practice. Add to it as the work becomes more serious. The adopter owns the thresholds and the lists in these pages; change them to match your situation, and write the change down.

## Ownership

Name one person per guardrail. They need not do the work, but they hear about breaches, decide exceptions and review the checks. For a small team, one person may own all six. Say so, and add a second person for the checks, since people are poor at auditing their own habits.

## What these pages are not

They are practical starting points, not legal advice or certification. Where the law or a contract sets a stronger duty, follow that. Where the pages mention data protection or sector rules, the adopter is responsible for knowing which apply to them.
