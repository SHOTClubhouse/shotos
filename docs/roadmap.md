# Roadmap

Each item ships when it has evidence behind it, not before.

## Available in the six-stage edition

- The six stages, four rules, twelve agent controls and six guardrails.
- 28 core skills covering every stage, and 12 packs with 60 more.
- Ways of working, role agents, review lenses and a cast file.
- Installer support for packs and role agents, and a Claude Code plugin per pack.
- An [enterprise risk review](guides/enterprise-risk-review.md) that connects pilot evidence to the four NIST AI RMF 1.0 functions.
- Outcome evals: ten fictional work scenarios, graded on what the agent produced, run with and without SHOTos on three Claude models. See the [evidence by build](evidence.md).

## Maturity gaps

| Area | What to improve | Evidence that would close the gap |
| --- | --- | --- |
| Documentation | Make the route from installation to an accepted task easy to follow | A first-time user completes a task and can find the output and evidence |
| Personas | Show what each role receives and hands forward | Someone can switch roles or hand work to a colleague without repeating intake |
| Marketing | Lead with a recognisable job and the output people get | A new reader can explain when to use it and tries a relevant skill |
| Skills | Deepen decisions and references where real work exposes a gap | An accepted output and a contrary case that exercises the corrected behaviour |
| Capability | Verify the tools and permissions each supported route actually needs | Read-back from the installed runtime and evidence of any authorised action |
| Canon | Keep the working agreement and installed instructions aligned | A fresh install carries the same source and checks across the runtimes tested |
| Single resource | Give each task one owning record and each instruction one source | The next operator can locate the current version, evidence and decision from that record |
| Workflows | Observe a full cycle after handoff | The receiving team runs independently and its lead accepts the evidence |
| Improvement metrics | Follow work through to human acceptance | Comparable first-pass acceptance, material defects, review and rework minutes, pickup time and reported spend |

Use the [full-pack guide](full-pack.md#improve-the-pack-from-real-work) to turn a task-level lesson into a reviewable change. Keep progress claims tied to the evidence recorded for that change.

## Next

- **Run one real programme:** agree a baseline and thresholds at Scope and Hypothesise, record the Track decision and observe an independent cycle before rollout.
- **Verify runtime setup:** open an installed stage skill in a fresh session, check access and approval paths, and record which platforms and runtimes were verified.
- **Check live automations:** run each Apps Script automation end to end in a test Google account and record what the account shows.
- **Measure work through acceptance:** capture review, rework and handoff time alongside agent runtime in the accepted-work ledger.

## Later

- **Enterprise bridge:** extend the workflow evidence guide for other risk and assurance processes.
- **Community packs:** a review process and quality gate for packs written by others.
- **Translations** of the method, templates and guides.
