# leaders-inbox

**One place for a leader's rough notes, links and ideas, reduced to meaning and routed to exactly one outcome.**

The agent reads a batch of raw input, writes one sentence of meaning for each item, labels statements as fact, hypothesis or target, checks for existing records, and recommends one route: a decision, a task in its owning project, shared context or, only if you ask, long-term memory. Recommendations come first.

It serves the Brief step. Rules: 2 Agree acceptance first, 4 Claim only what you can show.

## The problem it solves

The managing director of Northgate Cycles dictates six notes on the train: a supplier might raise prices, a competitor link looks interesting, someone should check warranty wording, and a half-formed idea about a loyalty scheme. Pasted into a task tool, all six become tasks, two duplicate existing ones, and the loyalty idea gets an owner it never agreed to.

With the skill, two items match existing tasks and are linked, one becomes a decision for the managing director, one becomes a scoped task with an owner to confirm, and the loyalty idea is marked "no record yet".

## When to use it, and when not to

Use it for batches of raw input from a leader. Skip it for one clear task, or for recording a decision already made.

## Who it is for

Founders, executives, chiefs of staff and heads of department who think out loud.

## How to use it

> Here are my notes from the week. Route them: tell me what you recommend, and check what we already have before creating anything.

Output uses [template.md](template.md). Worked example: [input](../../examples/leaders-inbox/input.md) and [output](../../examples/leaders-inbox/output.md).

## How it connects

- **Decisions:** hands to [decision-brief](../decision-brief/README.md).
- **Daily loop:** confirmed dates go to the [daily-brief](../daily-brief/README.md) ledger.
- **Earlier in the method:** [capture-the-problem](../../../../skills/capture-the-problem/README.md) for a problem worth testing.

## Needs

Read access to the task list, decision log or project notes you want matched. Write access only to the project notes you name. Without any, paste the existing records in.

**Evidence:** Tested in a paired run on 3 November 2026, one run per case, graded by meaning. Cases passed with SHOTos: Haiku 2 of 2, Sonnet 2 of 2, Opus 2 of 2. Without: Haiku 1 of 2, Sonnet 1 of 2, Opus 2 of 2. See [evidence](../../../../docs/evidence.md) for how to read this.

## Tips and common mistakes

- Say so when you want something remembered. The default is that nothing goes to long-term memory.
- Let items stay unfiled. A note with no home is not a failure.
- Give it the records to match against, or it will create duplicates.

## Limits

- It can only match records it can read.
- It reduces meaning from the words given; if a note is ambiguous it asks, it does not guess.
- It does not assign work to people. You or the project owner do that.
